## 2. المعمارية المقترحة

```
المتصفح (React)                       Django (tenant_auth)                 Orchestrator (FastAPI)                 GPU (Tailscale)
┌───────────────────────┐   ui_ctx   ┌──────────────────────┐             ┌───────────────────────────┐          ┌──────────────┐
│ AgentChatPanel        │──────────▶│ /api/ai/agent/chat/  │────────────▶│ 1) Intent Router (قواعد)  │─────────▶│ vLLM Qwen3-8B│
│  - فقاعات محادثة      │            │  - يحقن role/halaqat │             │ 2) Dialog State (Redis)   │          │ + LoRA       │
│  - أزرار خيارات/تأكيد │◀──────────│  - يحفظ المحادثة     │◀────────────│ 3) LLM + Tool loop        │          │ faster-whisper│
│  - TTS + STT          │ ui_actions │  - يُنقّي PII        │ ui_actions  │ 4) Action Validator       │          │ TTS (جديد)   │
│ UIActionExecutor      │            └──────────────────────┘             └───────────────────────────┘          └──────────────┘
│  (قائمة بيضاء)        │
└───────────────────────┘
```

### 2.1 مبدأ التصميم: «هجين» (قواعد + نموذج)
- **المسار السريع الحتمي (Deterministic Router):** أوامر التنقل والنوافذ وتسجيل الخروج تُحل **قبل** النموذج بمطابقة عربية مرنة (استخدام `arabic.normalize` الموجود) مقابل **سجل الشاشات** لكل دور. النتيجة: دقة ~100% وزمن أقل من 50ms وبلا GPU.
- **النموذج (Qwen3-8B + LoRA):** للغموض واللهجات والأوامر المركّبة والأسئلة المفتوحة وعمليات البيانات.
- **المصدر الوحيد للحقيقة (Single Source of Truth):** ملف `screen_registry` يُولَّد منه: (أ) روابط الواجهة، (ب) أدوات التنقل في الوكيل، (ج) وصف المنصة داخل الـ prompt، (د) بيانات التدريب. بذلك لا يتخالف الكود والتعليمات.

### 2.2 سجل الشاشات (Screen Registry)
مثال لإدخال (يُستخلص من `App.jsx` والأشرطة الجانبية):
```json
{
  "id": "students", "roles": ["teacher","center_manager","tenant_admin"],
  "route": "/{role_prefix}/students",
  "synonyms": ["الطلاب","تبويب الطلاب","قائمة الطلاب","صفحة الطلاب","طلابي"],
  "needs": []
},
{
  "id": "halaqa_sessions", "roles": ["teacher","center_manager","tenant_admin"],
  "route": "/{role_prefix}/rings/{halaqa_id}/sessions",
  "synonyms": ["الجلسات السابقة","جلسات الحلقة","سجل الجلسات"],
  "needs": ["halaqa"]
}
```
- `needs` هو ما يحدد «سؤال الحلقة أولاً»: إن وُجد معامل ناقص، يبدأ **حوار ملء الفراغات** بدل الرفض.
- تُرسل الواجهة مع كل رسالة `ui_context = {route, role, locale}`، ويُحقَّق منها في الخادم (لا يُثق بها للصلاحيات، فقط للسياق).

### 2.3 بروتوكول الإجراءات (UI Actions)
يرجع الـ Orchestrator مصفوفة `ui_actions` منظّمة (بدل الاعتماد على نص حر):

| type | الحقول | التنفيذ في الواجهة |
|---|---|---|
| `navigate` | `route`, `query?` | `navigate(route)` بعد التحقق أن المسار ضمن القائمة البيضاء لدور المستخدم |
| `open_modal` | `modal` ∈ {`change_password`, `new_session`, ...}, `props?` | عبر `AgentUIContext` (حدث عام) |
| `choices` | `options[{id,label,payload}]` | أزرار قابلة للضغط داخل المحادثة |
| `confirm` | `token`, `text` | بطاقة «نعم / لا» (أزرار موافقة ورفض) |
| `logout` | — | يُنفَّذ **فقط** بعد `confirm` ناجح: `logout()` ثم `navigate('/login')` |
| `speak` | `text`, `lang` | يغذّي TTS |

**قواعد الأمان:** الواجهة تتجاهل أي `route`/`modal` خارج قائمتها البيضاء؛ الخادم يتحقق من الدور مرة ثانية؛ كل ما يغيّر حالة (كتابة، تسجيل خروج) يمر عبر `confirm`؛ نتائج الأدوات تبقى «بيانات لا تعليمات» كما هو الآن.

### 2.4 حالة الحوار (Dialog State)
تُخزَّن في Redis بمفتاح `tenant:user:session` مع TTL (30 دقيقة كما الآن):
```json
{ "pending_intent": "open_student_profile",
  "slots": {"student": null},
  "awaiting": "student",
  "history": [ ...آخر 8 أدوار... ] }
```
- عند الإجابة بـ «أسامة الزين» يُدمج في `slots` وتُكمل النية الأصلية تلقائياً (يعالج الحالة 7).
- إلغاء تلقائي إن غيّر المستخدم الموضوع أو قال «ألغِ».
- يُنقل `_pending` و`_done` (idempotency) إلى Redis أيضاً مع TTL.

## 4. المحادثة والصوت (البند 10)

### 4.1 واجهة المحادثة
- استبدال شريط الأمر الواحد بـ `AgentChatPanel`: قائمة رسائل (مستخدم/مساعد)، حقل إدخال، زر ميكروفون، زر «محادثة جديدة»، سجل الجلسات السابقة.
- استخدام `/api/ai/agent/chat/` (موجود) مع `session_id` ثابت لكل محادثة، وإضافة بث SSE لاحقاً (`/v1/chat/stream` موجود في المثال ويُبنى عليه) لإظهار الرد تدريجياً.
- الاحتفاظ بالمحادثة في `sessionStorage` + الخادم، لتبقى عند التنقل بين الصفحات (المكوّن يُركَّب مرة واحدة في `MainLayout` فلا يُفقد عند `navigate`).
- ترحيل `agentService.js` ليتحدث مع مسار واحد معرّف، وحذف مسار `/api/agent/command/` غير الموجود.

### 4.2 الصوت
- **الإدخال (STT):** الإبقاء على Web Speech ثم MediaRecorder → faster-whisper، **مع إصلاح الكود المكرر (البند G)** وتبسيط الدالة: طلب الإذن مرة واحدة فقط.
- **الإخراج (TTS) على مرحلتين:**
  1. **فوراً بلا GPU:** `window.speechSynthesis` بلغة `ar-SA` لقراءة حقل `speak`. جودة الأصوات تختلف بحسب الجهاز.
  2. **لاحقاً:** خدمة TTS عربية على الخادم (انظر قسم الـ GPU). يجب اختبار الجودة العربية فعلياً قبل الاعتماد (مرشحات للتجربة: Piper صوت عربي، أو MMS-TTS للعربية). لا أعد بنتيجة قبل التجربة.
- **وضع الصوت:** إن سأل المستخدم صوتياً يرد صوتياً + نصياً. إن كتب يرد نصياً فقط. زر كتم، وإيقاف الصوت فور بدء المستخدم بالكلام (barge-in).
- **السلامة:** يُقرأ نص التأكيد بوضوح قبل أي كتابة، والتأكيد الصوتي «نعم/لا» يمر عبر `parse_confirmation` الموجود، وتبقى مهلة 60 ثانية.

## 5. تخزين المحادثات وتحسين النموذج (البند 11)

### 5.1 أين وكيف
- **التخزين في Django (قاعدة بيانات المستأجر) لا في الـ Orchestrator.** يبقى الـ Orchestrator بلا حفظ نصوص (يحافظ على قراره الأمني الحالي)، وDjango يعرف المستخدم والمستأجر والموافقة.
- نماذج مقترحة (ملف `backend/core_system/ai_assistant/models.py` جديد + هجرات `tenant_template`):

| النموذج | الحقول الأساسية |
|---|---|
| `AgentConversation` | `id`, `user_id`, `role`, `channel` (text/voice), `started_at`, `ended_at`, `consent_for_training` |
| `AgentMessage` | `conversation`, `seq`, `role` (user/assistant/tool), `text_redacted`, `tool_calls` (JSON), `ui_actions` (JSON), `outcome`, `model`, `prompt_version`, `latency_ms`, `injection_flagged` |
| `AgentFeedback` | `message`, `rating` (👍/👎), `correction_text?`, `reason` |

### 5.2 الخصوصية (إلزامي لأنها بيانات دينية/أطفال)
- **إخفاء PII قبل الحفظ:** نعيد استخدام `security.py` (هواتف، هويات، بريد) ونضيف **ترميز أسماء الطلاب** إلى `{{STUDENT_1}}` في نسخة التدريب. نحتفظ بالمحادثة الأصلية للمستخدم فقط (للعرض)، ونسخة مُنقّاة للتدريب.
- **موافقة صريحة:** إعداد على مستوى المسجد (`consent_for_training`) + إشعار واضح في واجهة المساعد. لا تُصدَّر محادثة بدون موافقة.
- **مدة الاحتفاظ:** المقترح 180 يوماً للنص الخام، والنسخة المُنقّاة المعتمدة للتدريب أطول.
- **عزل المستأجرين:** لا خلط بين المساجد في التصدير إلا بعد الإخفاء والموافقة.
- **الحذف:** المستخدم يحذف محادثاته، وتُحذف النسخ المشتقة غير المستخدمة بعد.

### 5.3 دورة التحسين (Data Flywheel)
1. **الالتقاط:** كل رسالة + أداة + نتيجة + تقييم 👍/👎.
2. **الفرز الليلي:** يختار تلقائياً: محادثات نجحت (نُفّذت أداة وأُكّدت)، ومحادثات فشلت (`needs_clarification` متكرر، 👎، رفض). تُرتَّب حسب الأهمية.
3. **المراجعة البشرية:** شاشة بسيطة للمشرف التقني تصحح «الأداة/المعاملات الصحيحة» لأسوأ 50 حالة أسبوعياً.
4. **التحويل:** تحويل الحالات المصححة إلى نفس صيغة `gpu-stack/data/train.jsonl` (system + user + tool_calls)، بعد التحقق بـ `validate_dataset.py`.
5. **الدمج والتدريب:** `build_mixed_dataset.py` ثم `run_train.sh` (إصدار v3).
6. **البوابة:** لا نشر ما لم يتفوق على v2 في `compare_eval.py` على المجموعة الذهبية + مجموعة الانحدار (القسم 7).

## 6. تحسينات جودة النموذج والـ Prompt

1. **فصل النموذجين وظيفياً:** استخدام `temperature=0` لمرحلة اختيار الأداة (الإعداد الحالي 0.1 في `agent_chat`) ورفعها قليلاً فقط لصياغة الرد الودي.
2. **تعليمات حسب الدور:** prompt المعلم يختلف عن المدير (الحالي «للمعلمين» فقط) ويُولَّد جزء «معلومات المنصة» من سجل الشاشات تلقائياً.
3. **معالجة `tool_calls` المتعددة** وتنفيذ القرائية منها تباعاً، مع إيقاف الحلقة عند أول كتابة يحتاج تأكيداً (إصلاح البند I).
4. **توضيح بأزرار** بدل نص حر: `NeedClarification.options` موجود بالفعل في `agent_tools.py`؛ نمرره كـ `choices` للواجهة.
5. **تقليل حجم السياق:** أدوات كثيرة ستكبّر الـ prompt. الحل: إرسال أدوات الدور فقط (موجود) + أدوات التنقل كأداة واحدة `open_screen(screen_id, ...)` بدل أداة لكل شاشة، لتبقى المواصفات قصيرة.
6. **التطابق الصوتي العربي:** `resolve_student/resolve_halaqa` تحمّل كل الطلاب في كل نداء، فنضيف بحثاً على الخادم (`?search=`) أو تخزيناً مؤقتاً قصيراً، ونعالج الأخطاء الصوتية الشائعة (ة/ه، ى/ي، همزات، «ابن/بن»).
7. **ردود صادقة:** إن لم تتوفر ميزة لدور المستخدم، يقول ذلك ويقترح أقرب شاشة بدل «لا أستطيع».
8. **ضبط `halaqat_ids` للمعلم:** يُحسب حالياً بمطابقة نصية لاسم المستخدم مع `teacher_name` (`views.py:58-65`)، وهذا هش. يجب اعتماد مفتاح علاقة (FK) إن وُجد، وإلا فاحتمال الخطأ في الصلاحيات قائم.

## 7. القياس والاختبار (بوابة الجودة)

- **مجموعة انحدار** تُضاف إلى `orchestrator/eval/golden_ar.json`: الأوامر الإحدى عشرة حرفياً + كل مرادفاتها + لهجات (فصحى/شامية/خليجية) + أخطاء إملائية/صوتية، لكل دور (معلم/مدير/مسجد).
- **مقاييس:** دقة اختيار الأداة/الشاشة، دقة المعاملات، نسبة السؤال غير الضروري، نسبة التنفيذ بلا تأكيد (يجب 0%)، زمن الاستجابة p50/p95.
- **اختبارات Playwright** من الطرف إلى الطرف: يكتب «انقلني إلى تبويب الطلاب» ويتحقق أن `location.pathname` تغيّر فعلاً، ويضغط «نعم» في تسجيل الخروج ويتحقق من العودة إلى `/login`.
- **اختبارات وحدة** على Router وDialog State وValidator المسارات (رفض مسار خارج دور المستخدم).
- يُدمج كل ذلك في CI ويُمنع الدمج عند هبوط أي مقياس.

## 8. ما يجب عمله على جهاز الـ GPU

الوضع الحالي (من الكود): RTX 5070 Ti بسعة 16GB، وvLLM FP8 يحجز ~80% (~12.4GB)، وSTT على CPU، والخدمات على Tailscale فقط.

### 8.1 ميزانية الذاكرة والقرار
| الخيار | الوصف | المخاطر |
|---|---|---|
| **أ (موصى به الآن)** | إبقاء vLLM كما هو، TTS الأول في المتصفح، وSTT على CPU. صفر تغيير على الكرت. | زمن STT على CPU أعلى |
| ب | تشغيل TTS على CPU في حاوية منفصلة. | يستهلك CPU ويؤثر على STT إن تزاحما |
| ج | إعادة بناء صورة STT بـ CUDA يدعم Blackwell، وتشغيل Whisper على GPU (~1.5GB)، مع خفض `--gpu-memory-utilization` من 0.80 إلى ~0.70. | KV cache أصغر وتزامن أقل. **يتطلب اختباراً** |
| د | تحويل النموذج إلى AWQ 4-bit لتحرير ذاكرة. | **غير مُختبر** (كما يذكر `up.sh`)، قد تتأثر جودة العربية |

### 8.2 قائمة المهام على جهاز GPU (بالترتيب)
1. **فحص ما قبل التنفيذ:** `nvidia-smi`، التأكد من الذاكرة الحرة، نسخ احتياطي لمجلد `gpu-stack/loras/` (يحوي المحوّلات الحالية) ولملف `.env`.
2. **سحب الكود الجديد:** `git pull` على فرع الميزة، والتحقق من `docker compose config` دون أخطاء.
3. **إعدادات vLLM للاختبار (واحدة تلو الأخرى مع قياس):**
   - `--enable-prefix-caching` (إن لم يكن مفعلاً افتراضياً في الإصدار المستخدم) لأن الـ system prompt والأدوات ثابتة فتتسارع الردود.
   - `--kv-cache-dtype fp8` لمضاعفة سعة KV تقريباً، ثم اختبار رفع `--max-model-len` إلى 6144 و`--max-num-seqs` إلى 6. **يُقاس أثره على جودة العربية قبل الاعتماد.**
4. **توليد بيانات v3 (يمكن على أي جهاز بلا GPU):** `python gpu-stack/training/generate_dataset.py` بعد إضافة أدوات UI وحالات الحوار. تُنقل `data/*.jsonl` إلى الجهاز.
5. **التحقق من البيانات:** `validate_dataset.py`، وفحص عدم تسرب الأمثلة الذهبية.
6. **التدريب (توقف مؤقت للاستدلال):** جدولة `ADAPTER_NAME=manarasy-qwen3-v3 TRAIN_FILE=... VAL_FILE=... training/run_train.sh` **خارج ساعات الدوام** لأنه يوقف vLLM. السكربت يعيد تشغيل الاستدلال تلقائياً عند الانتهاء أو الخطأ. أثناء التدريب تعمل المنصة بالرسالة البديلة اللطيفة (موجودة).
7. **المقارنة:** `compare_eval.py` بين v2 وv3 على المجموعتين (الذهبية + الانحدار).
8. **النشر التدريجي (Canary):** `LORA_MODULES="manarasy=manarasy-qwen3-v3 manarasy_v1=manarasy-qwen3-v1 manarasy_v2=manarasy-qwen3-v2"` ثم `./up.sh restart`، وتوجيه نسبة صغيرة من الطلبات لـ v3 عبر متغير `VLLM_MODEL_AGENT` أو أداة `eval/ab_endpoints.py` الموجودة. **الرجوع:** إعادة الاسم إلى v2 وتشغيل `up.sh restart`؛ تبقى المحوّلات القديمة على القرص.
9. **خدمة TTS (عند اعتماد الخيار ب أو ج):** إضافة خدمة في `docker-compose.yml` تستمع على `${TS_IP}` فقط، مع healthcheck، ثم اختبار جودة عربية بـ 30 جملة من الحلقات قبل التفعيل.
10. **المراقبة:** استخدام `/metrics` الموجود في الـ Orchestrator ومقاييس vLLM، وتنبيه عند: p95 > 8 ثوانٍ، أو هامش VRAM < 2.5GB (حد `MIN_MARGIN_MB`)، أو انفتاح الـ circuit breaker.
11. **الأمان:** إبقاء كل المنافذ على Tailscale فقط، وعدم نقل بيانات المحادثات الخام إلى الجهاز؛ تُنقل **النسخة المُنقّاة والمُوافَق عليها** فقط.

> تقدير زمن التدريب غير مذكور في الكود ولا أخمّنه؛ سنقيسه من أول تشغيل ونعتمده في الجدولة.

## 10. المخاطر والقرارات المفتوحة

- **تنفيذ إجراء خاطئ:** أي أداة تغيّر حالة تبقى خلف `confirm`، ومسارات الواجهة بقائمة بيضاء، ولا ينفّذ النموذج تنقلاً لم يُتحقق منه.
- **تضخم السياق (4096):** نراقب طول الـ prompt في كل مرحلة؛ إن اقتربنا من الحد نفعّل خيار KV fp8 أو نختصر الأدوات.
- **جودة TTS العربي:** غير مضمونة؛ لذلك الدخول التدريجي.
- **خصوصية الأطفال:** قرار الموافقة (على مستوى المسجد أم ولي الأمر؟) قرار سياسي/قانوني تحتاج حسمه قبل P4.
- **قرارات أحتاجها منك:** (1) موقع «النقاط» للمعلم، (2) مدة الاحتفاظ بالمحادثات، (3) هل نبدأ بالخيار أ أم ج للـ GPU، (4) هل تريد دعم الطالب وولي الأمر في الوكيل لاحقاً (الآن `STAFF_ROLES` فقط).
